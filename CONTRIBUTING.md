# Contributing to Universal Deliberation Protocol

**Thank you for helping improve UDP.** The goal is one rigorous, portable and evidence-conscious protocol for all compatible AI models, providers, projects and agents.

**Original creator:** Noureddine Eddars  
**Initial publisher / repository:** EddarsGlobal (`eddarsglobal`)

## Before contributing

1. Read the current [canonical specification](universal_deliberation_protocol_v2.1.0.md), the existing issues and relevant prior work before proposing duplicates.
2. For defects, identify the article or paragraph, the exact scenario, expected behavior, observed problem, and evidence or counterexample. Separate tested results from hypotheses.
3. For new obligations, explain the risk addressed, cross-provider portability, tradeoffs, failure modes and impact on existing adopters.
4. Proposals must preserve **one UDP**. Do not create Lite/Core/Full editions or make any named project, product, API or LLM a universal dependency.
5. For interoperability or quality claims, include reproducible evaluation methods and negative findings when known. Never claim `PASS` or `CERTIFIED` without the matching checks.

## Ways to help

- **Issues:** report ambiguities, internal contradictions, incorrect claims, portability failures, security concerns, and evaluation gaps.
- **Pull requests:** corrections, better definitions, concrete examples, test cases, schema improvements, translations and audited documentation.
- **Evidence:** publish reproducible comparisons, baseline results, counterexamples, false-positive rates and confidence limits.

## Pull request checklist

- [ ] Existing material was reviewed; duplication or overlap is explained.
- [ ] Changed provisions and motivations are explicit.
- [ ] `MUST`, `SHOULD`, `MAY` are used deliberately and consistently with BCP 14.
- [ ] Provider-neutral scope and current attribution are preserved.
- [ ] Any affected cross-references, tests, examples and changelog entries are updated.
- [ ] No invented model tests, production deployments, compliance verdicts or independent endorsements are asserted.
- [ ] Proposed normative changes are labeled as proposals until merged by maintainers.

## Collaboration

Be technical, precise, respectful and open to falsification. Criticism of ideas is welcome; fabricated evidence, harassment and unsupported personal accusations are not. Discussion can be candid without becoming hostile.
